# 1번 작업 회고 — 2~5번에 적용할 학습 가이드

이 문서는 1번(OBST)을 만들면서 "처음 설계엔 없었지만 결국 추가해야 했던 것들"을 정리한다.
2~5번은 알고리즘 자체가 1번보다 어려우니 처음부터 같은 수준의 시각화·쉬운 설명을 끼워넣어야 한다.

---

## 1. 처음에 빠뜨려서 사후에 추가한 것들

### 1-1. 알고리즘 자체보다 그 *밑바닥 개념*부터 설명해야 한다
처음 디자인은 "DP 워밍업 셀(피보나치) → OBST 점화식"로 가볍게 갔지만,
사용자가 "DP가 뭔지부터 모르는 사람도 이해할 수 있게"를 요구해 **Cell 00** 을 통째로 추가:
- 알고리즘 설계 패러다임 비교 (Greedy / Divide & Conquer / DP)
- DP의 두 조건 (최적 부분 구조 + 중복 부분 문제)
- Top-down(메모화) vs Bottom-up(타뷸레이션)
- **DP 문제 풀이의 5단계 절차** (상태 → 점화식 → 기저 → 채우는 순서 → 최종 답)
- 피보나치 재귀 트리 SVG로 "중복" 시각화

**교훈**: 문제별 알고리즘을 다루기 전, 그 알고리즘이 속한 *부류*(DP, 그래프 탐색, 최대 유량 등)의 기초를 별도 셀로 깔고 들어가야 한다.

### 1-2. 표기·인덱싱 컨벤션은 거의 항상 헷갈린다
입력 데이터 표에서 $p_i, q_i$ 같은 열에 있는 게 별개 사건임을, 그리고 "$i$"가 두 행에서 다른 걸 가리킨다는 점을 사용자가 두 번 질문함. 이걸 풀려고:
- 콜아웃에 "$i$가 뭐를 가리키나" 명시
- 수직선 그림에 키(점)와 틈(구간)을 시각적으로 분리
- 표 헤더에 부제목 추가 ("위치 i", "i번째 키 k_i 찾기", "i번째 틈")

**교훈**: 새로운 표기가 등장할 때마다 — 특히 인덱스가 0부터 시작하는지 1부터인지, 같은 기호가 여러 의미인지 — 한 번 더 명시적으로 풀어줘야 한다.

### 1-3. "왜?" 설명이 부족했다
점화식 $C[i,j] = \min(\ldots) + W[i,j]$ 에서 "왜 $W$를 더하나"는 핵심 직관인데 초안엔 식만 있었음.
"루트가 생기면 모든 노드 깊이가 1 늘어남 → 비용 증가 = 각 노드 확률 × 1 → 합치면 $W$" 콜아웃을 사후 추가.

**교훈**: 식의 각 항이 *왜 거기 있는지* 한 줄로 곁들이지 않으면 "외워야 하는 식"이 된다. 모든 항에 대해 "이게 왜 더해지/곱해지는가?" 물어보고 답을 쓰자.

### 1-4. 비유 — 추상 개념을 현실로 끌어내리기
- 더미 노드 → "전화번호부에 없는 이름 찾기"
- 최적 부분 구조 → "회사 전체가 효율적이려면 모든 팀도 효율적"

**교훈**: 추상 개념 하나에 짧은 비유 한 줄. 정확성보단 *이미지가 떠오르는지*가 기준.

## 2. 효과 본 시각화 카탈로그 (재사용 가능한 유형)

다음은 1번에서 통한 시각화 유형들 — 2~5번에도 비슷한 형태로 응용 가능.

| # | 시각화 유형 | 1번에서의 용도 | 일반화 |
|---|---|---|---|
| V1 | **재귀 호출 트리 SVG** + 중복 노드 색칠 | 피보나치 중복 부분 문제 시각화 | DFS, 재귀 분할 등 |
| V2 | **막대 차트** (큰 값 강조 색) | p, q 확률 분포 → "어느 게 크냐" 직관 | 입력 분포·빈도·가중치가 있는 모든 문제 |
| V3 | **수직선 + 점/구간** 분리 | 키(점) vs 틈(구간) 시각적 구분 | 두 가지 다른 객체가 인덱스를 공유할 때 |
| V4 | **확장된 트리/그래프 다이어그램** (작은 예시) | 키 노드 + 더미 노드 배치 | 새 개념 도입 시 항상 *작은* 예시 그림 한 장 |
| V5 | **서브트리 강조 그림** (점선 박스) | "이 부분도 OBST" — 최적 부분 구조 | 재귀적 구조 가지는 모든 문제 |
| V6 | **(i,j) 격자 + 대각선 색상 그라데이션** + 화살표 | 부분 문제 채우는 순서 | 구간 DP, 매트릭스 DP |
| V7 | **점화식 분할 그림** (왼·오 + 비용 식 옆에) | $C[i,j]$에서 루트 $m$ 선택 → 좌/우 갈라짐 | 분할 점화식, 트리 DP |
| V8 | **단계별 표 채우기 인터랙티브** (Next/Prev/Reset/Skip) | W·C·R 64 스텝 | 모든 DP, BFS 거리표, 유량 증가 등 |
| V9 | **최종 결과 트리/그래프** + 클릭 인터랙션 | OBST 트리, 키 검색 경로 빨강 | 결과 자료구조에 사용자가 질의해보게 |
| V10 | **수식 옆에 직관 박스** | "왜 $W$를 더하나" 콜아웃 | 점화식·중요 식 옆에 항상 |

### UX 측면에서 효과 본 것
- **셀 단위 노트북 레이아웃** + 상단 스테퍼 (셀 점프 + 진행도)
- **플로팅 컨트롤 패널** (스크롤 따라옴 + 숨기기) — 단계별 실행 시 손이 늘 닿게
- **`<details>` 코드 토글** (의사코드/실제 코드 접기) — 기본 접힘, 원하는 사람만 펴기
- **공통 CSS/JS** (`assets/`) → 5문제 일관된 룩

## 4. 2~5번에 미리 준비할 것

각 문제별로 예상되는 어려움과 필요한 시각화·설명 후보.

### 문제 2 — 브리지 (DFS 기반 disc/low)

**예상되는 어려움**
- 그래프·DFS·트리(스패닝)가 처음인 사람에게는 그래프 표기부터 짚어야 함
- `disc[u]` (방문 시각)와 `low[u]` (도달 가능한 최저 disc) — 특히 `low`의 정의가 헷갈림
- 왜 $\text{disc}[u] < \text{low}[v]$ 이면 브리지인가? 직관이 비자명
- 무방향 간선에서 "부모"라는 개념의 모호함 (양방향이라)
- 백 에지(back edge) vs 트리 에지(tree edge)

**필요 셀 후보 (대략 10~12개)**
- 00 — 그래프란? (정점·간선·인접 리스트), DFS 한 단계씩
- 0 — 이 페이지에서 뭘 할 것인가
- 1 — 브리지란 무엇인가 (제거하면 연결 끊김), 일상적 예시 (다리, 단일 통신선)
- 2 — 무식한 방법: 간선 하나씩 빼보고 BFS — 왜 비싼지 ($O(VE)$ 또는 $O(E(V+E))$)
- 3 — DFS 스패닝 트리 개념 (트리 에지 vs 백 에지)
- 4 — `disc[u]` (방문 시각) 정의 + 작은 그래프에서 직접 적어보기
- 5 — `low[u]` 정의 — 가장 헷갈리는 부분. **단계별 시각화 필수**
- 6 — 판별 조건 $\text{disc}[u] < \text{low}[v]$ 직관 ("v의 서브트리에서 u 위로 못 올라감")
- 7 — 알고리즘 단계별 실행 (DFS 트리 그려가며 disc/low 갱신)
- 8 — 모든 브리지 출력 + 특정 간선 판별 데모
- 9 — 시간복잡도 $O(V+E)$, 사용 사례 (네트워크 신뢰성)

**시각화 후보**
- DFS 진행을 따라가는 애니메이션 (V8 — Next 버튼). 노드 위에 disc/low 두 값을 표시.
- 백 에지를 점선·다른 색으로 (트리 에지는 굵게).
- 브리지 후보 간선이 발견될 때 빨강 펄스 + 그 간선만 제거한 그래프 비교 (V4·V5).
- 사용자가 그래프 입력 가능 (정점 수 + 간선 페어, `-1 -1`로 종료) → 시각화 즉시 갱신.
- "특정 간선 판별" UI: 두 정점 선택하면 그 간선이 브리지인지 색으로 표시.

**비유 후보**: "다리(bridge)" 그대로 — 강을 건너는 단 하나의 다리가 끊기면 두 마을이 단절. 통신망의 단일 회선.

### 문제 3 — 탈출 문제 (Maximum Flow, Edmonds-Karp/Dinic)

**예상되는 어려움**
- 최대 유량 자체가 어려운 개념. 용량·유량·잔여·증가 경로 모두 새로움.
- 정점 분할 (in/out 노드)이 왜 필요한지 — 노드 용량을 간선 용량으로 바꾸는 트릭
- 그리드를 네트워크로 변환하는 단계 — 추상화 점프 큼
- BFS로 증가 경로 찾고 잔여 그래프 갱신 → 역방향 간선이 생기는 이유
- Edmonds-Karp vs Dinic 차이 (level graph, blocking flow)

**필요 셀 후보 (대략 12~14개)**
- 00 — 그래프 + 방향 간선 + 가중치(용량)
- 01 — 최대 유량이 뭐냐 (수도관 비유 — 시작점에서 끝점으로 물 흘리기)
- 0 — 이 페이지에서 뭘 할 것인가 (탈출 문제 정의)
- 1 — 탈출 문제 직관: 격자, 출발점들, 경계 = 안전, 겹치지 않는 경로 찾기
- 2 — 무식한 방법: 경로 하나씩 찾아 빼기 — 왜 부족한가 (예: 막다른 길)
- 3 — 그래프 → 유량 네트워크 변환 (정점 = 격자 칸, 간선 = 인접 칸)
- 4 — 정점 용량 1을 위한 in/out 노드 분할 (그림으로!)
- 5 — 가상 소스 $S$, 가상 싱크 $T$ 연결
- 6 — Ford-Fulkerson 원리 (증가 경로 + 잔여 그래프) — **작은 예시로**
- 7 — 잔여 그래프와 역방향 간선의 의미 (왜 필요한가)
- 8 — Edmonds-Karp = BFS로 증가 경로
- 9 — 알고리즘 단계별 실행 (격자 위 경로 + 잔여 그래프 동시 보기)
- 10 — 결과: 격자 위에 탈출 경로들 색칠, 불가능 케이스 예시
- 11 — 복잡도 ($O(VE^2)$), Dinic 한 줄 언급

**시각화 후보**
- 격자에 출발점들 마킹, 경계 강조.
- **격자 → 네트워크 변환 시각화**: 격자 한 칸을 클릭하면 in/out 두 노드로 분리되는 애니메이션.
- 증가 경로를 BFS로 찾는 과정 (격자 + 네트워크 두 뷰 동시).
- 잔여 그래프 별도 패널 — 정방향 용량 줄고 역방향 용량 늘어나는 것 시각화.
- 최종 격자 위에 색깔별 경로 (몇 명이 탈출했나).
- 사용자 입력으로 격자 크기·출발점 변경 가능하게.

**비유 후보**: 수도관 (용량) + 양수기, 화재 대피 시나리오 (출발점 = 사람들 위치, 출구 = 경계).

### 문제 4 — 무선 네트워크 (연결 성분 분할)

**예상되는 어려움**
- 비교적 단순 (Union-Find 또는 BFS/DFS로 컴포넌트)
- 3D 거리 계산이 처음이면 약간 헷갈림
- "멀티홉" 개념 — 직접 안 닿아도 다른 노드 거쳐 닿음

**필요 셀 후보 (대략 7~9개)**
- 00 — 그래프 기초 + 연결 성분이 뭐냐
- 0 — 이 페이지에서 뭘 할 것인가
- 1 — 3D 공간의 점들 — 시각화 (회전 가능한 3D? 또는 두 평면 투영)
- 2 — "직접 연결": 거리 ≤ $r$, 유클리드 거리 공식
- 3 — "멀티 홉" — 그래프 에지 만든 뒤 BFS/DFS로 연결성
- 4 — Union-Find (Disjoint Set) — 자료구조 도입
- 5 — 알고리즘 단계별 실행
- 6 — 결과: 컴포넌트별 색칠된 점 집합 + 각 집합 원소 출력
- 7 — 마무리, 다른 응용 (LAN 분할, 클러스터링)

**시각화 후보**
- **3D 점 시각화** (Three.js 또는 두 개의 2D 투영). 회전·줌 가능.
- $r$ 슬라이더 — 늘리거나 줄이면 에지·컴포넌트 실시간 변화 (가장 인사이트풀할 듯).
- 점들이 같은 컴포넌트끼리 같은 색.
- Union-Find의 부모 포인터 트리 시각화 (path compression 전후 비교).

**비유 후보**: 무전기 통화 가능 거리 — 자기들끼리 직접 통화 안 돼도 중계 가능. 와이파이 메시.

**난이도 평가**: 1번보다 쉬울 수도 있음. 시각화 ($r$ 슬라이더 + 3D)에 시간 더 쓸 여유.

### 문제 5 — 최소 비용 최대 유량 (MCMF) / 작업 배정

**예상되는 어려움**
- **이 시리즈에서 가장 어렵다.** 최대 유량(3번) + 음수 가중치 최단 경로(SPFA/Bellman-Ford) + 이분 매칭 모두 결합.
- 음수 비용이 잔여 그래프의 역방향 간선에서 자연스럽게 생긴다는 점 — 직관 비자명.
- 왜 Dijkstra 못 쓰나? 음수 가중치 때문 — 이걸 SPFA로 보완.
- 매칭은 익숙해도 "최대 매칭 + 최소 비용"이라는 합쳐진 목표는 새로움.

**필요 셀 후보 (대략 14~16개) — 가장 길어질 페이지**
- 00 — 그래프·최단 경로 기초 (Dijkstra와 Bellman-Ford 차이, 음수 가중치 이슈)
- 01 — (3번을 안 봤다면) 최대 유량 요약 셀
- 0 — 이 페이지에서 뭘 할 것인가 (작업 배정 문제)
- 1 — 이분 그래프와 매칭 (작은 예시 — 사람-직장 짝짓기)
- 2 — 비용 행렬 $C_{ij}$ — 어떤 배정이 좋고 나쁜가
- 3 — 무식한 방법: 모든 순열 시도 — $N!$ 폭발
- 4 — 그래프 모델링: 소스 → 작업자 → 작업 → 싱크, 용량 1, 비용 $C_{ij}$
- 5 — 잔여 그래프와 역방향 간선의 비용 (음수)
- 6 — 왜 Dijkstra 못 쓰나, SPFA/Bellman-Ford 도입
- 7 — MCMF 알고리즘 한 사이클 = 최단 경로 찾기 + 유량 1 흘리기
- 8 — 단계별 실행 — N번 반복
- 9 — 결과: 배정 쌍 + 총 비용 + 경로 다시 보기
- 10 — 복잡도 + 헝가리안 알고리즘 한 줄 언급
- 11 — 다른 응용 (스케줄링, 광고 입찰 배정)

**시각화 후보**
- 이분 그래프 (왼쪽 작업자, 오른쪽 작업) + 비용 행렬 격자 한 칸 호버 시 해당 간선 강조.
- **소스·싱크 추가된 네트워크 그림** — 4번 셀에서 단계별로 그려나가는 식.
- 잔여 그래프 옆에 별도 패널, 음수 비용 빨강.
- SPFA 큐가 어떻게 도는지 시각화 (현재 큐, 거리 배열 갱신).
- 매번 경로 하나 발견 → 매칭 1쌍 확정 → 격자에 체크 (V8 단계별 실행).
- 최종 매칭 결과: 비용 행렬에서 선택된 칸들 강조 (대각선 아닐 가능성 있음).

**비유 후보**: 임팩트 큰 비유 필요. "사람마다 잘하는 일이 다른데, 모두에게 일을 하나씩 줘서 총 작업 시간을 최소화" — 또는 택시 배차 (기사-승객 매칭).

**난이도 평가**: 1번의 1.5~2배 분량 + 깊이. **가장 먼저 브레인스토밍을 시작하고 가장 늦게 마치는 게 좋다.**
