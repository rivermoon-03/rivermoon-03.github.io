문제 4 · 무선 네트워크

3D 공간에 흩어진 정점들. 전파 도달거리 $r$ 이내면 직접 연결되고, 다른 정점을 거쳐 도달할 수도 있다(멀티 홉). 전체가 하나로 묶이는지, 아니면 몇 덩어리로 분리되는지 알아본다.

📋 문제 4 원문 (보고서 제출 기준)

3차원 공간에 $n$개의 정점이 주어져 있다. 각 정점마다 $x, y, z$ 좌표가 정수로 주어져 있다. 거리 $r$ (실수이며 전파 도달거리)이 입력으로 주어졌을 때 두 정점 사이가 $r$보다 작거나 같으면 직접 연결된다.

이제 두 정점끼리 직접 연결은 안되어도 몇 개 건너 두 정점끼리 도달할 수 있으면 멀티 홉(multi-hop)으로 연결된다.

주어진 정점이 전체 하나의 무선망으로 연결되는지, 그렇지 않으면 몇 개의 무선망으로 구성되어 있고 그 개수에 따른 partition (정점을 그 개수의 서로소 집합으로 분리)을 구하고, 각 집합마다 원소가 되는 정점들을 구하시오.

CELL 00 · 워밍업

먼저 — 그래프와 연결 성분이 뭔가요?

그래프(Graph)는 점들과 점들을 잇는 선들의 모음이다. 점은 정점(vertex, node), 선은 간선(edge)이라 부른다.

핵심 용어 한 번에.
  • 정점 $V$ — 그래프 안의 각 점. 사람, 도시, 무선 기기 등을 추상화한 것.
  • 간선 $E$ — 두 정점을 잇는 연결. 친구 관계, 도로, 통신 가능 여부 등.
  • 그래프 $G = (V, E)$ — 정점 집합과 간선 집합으로 정의.
  • 이웃(neighbor) — 어떤 정점과 직접 간선으로 연결된 정점들.

"연결되어 있다"는 뜻

두 정점이 연결됐다(connected)는 건, 그 사이를 잇는 경로(path)가 있다는 뜻. 직접 간선이 없어도 다른 정점들을 거쳐 도달할 수만 있으면 OK.

예: 정점 1에서 4로 가려면 1 → 2 → 4 또는 1 → 3 → 4. 직접 간선은 없지만 경로가 있으므로 연결됨. 반면 1과 5는 어떤 경로로도 갈 수 없으니 연결 안 됨.

연결 성분(Connected Component) = 서로 모두 연결되어 있고 외부 정점과는 연결되지 않은 정점들의 최대 부분집합.
위 예시는 그래프 전체가 2개의 연결 성분으로 나뉜다.

이 페이지에서 풀 문제는 결국…

"주어진 정점들이 몇 개의 연결 성분으로 나뉘는가, 각 성분에 어떤 정점들이 들어가는가"를 구하는 것. 다만 간선이 미리 주어지지 않고, 3D 좌표와 전파 거리 $r$에서 우리가 직접 만들어야 한다.

CELL 0 · 시작

이 페이지에서 뭘 할 거예요

3D 공간에 무선 기기 20개가 흩어져 있다. 각 기기의 좌표 $(x, y, z)$가 주어지고, 전파 도달 거리 $r$도 주어진다. 거리가 $r$ 이내인 두 기기는 직접 통신 가능, 그게 아니어도 다른 기기를 거쳐 통신할 수도 있다 — 멀티 홉(multi-hop).

목표: 이 20개 기기가 전체 하나의 무선망인지, 아니면 몇 개로 쪼개졌는지 알아내는 것.

사전 지식 없어도 OK. 그래프가 뭔지부터 짚었고(셀 00), 거리 계산도 차근차근 본다.

완성하면 이런 게 나옵니다

  • 3D로 회전 가능한 정점 시각화 (마우스 드래그)
  • $r$ 슬라이더를 움직이면 연결망이 실시간으로 합쳐지고 갈라지는 인터랙티브 뷰
  • Union-Find로 연결 성분을 한 간선씩 합쳐가는 단계별 시각화
조작법: 3D 뷰는 마우스 드래그로 회전, 휠로 줌. 상단의 동그란 점들을 누르면 해당 셀로 이동.
CELL 1 · 개념

3D 공간에 점들이 있다고 상상하면

모든 정점에 좌표가 있다. $i$번 정점은 $(x_i, y_i, z_i)$. 이번 페이지에서는 20개의 점이 미리 정해진 좌표에 놓여 있다.

아래 3D 뷰를 마우스로 회전해보면 점들이 어떤 패턴으로 흩어져 있는지 보인다 — 큼직한 덩어리 3개와 몇 개 떨어진 점들.

마우스 드래그 = 회전 · 휠 = 줌

이 점들이 무선 기기라고 치고, 다음 셀에서 "어떤 두 기기가 직접 통신 가능한가"를 정의한다.

CELL 2 · 개념

직접 연결의 조건: 거리 ≤ r

두 점 $A = (x_1, y_1, z_1)$과 $B = (x_2, y_2, z_2)$의 유클리드 거리:

$$d(A, B) = \sqrt{(x_1 - x_2)^2 + (y_1 - y_2)^2 + (z_1 - z_2)^2}$$

2D 피타고라스 공식의 3차원 버전이다. 한 축이 추가됐을 뿐.

왜 이 식이 거리인가? 2D에서 두 점 사이 거리는 직각 삼각형의 빗변 길이 → $\sqrt{(\Delta x)^2 + (\Delta y)^2}$ (피타고라스). 3D에서는 한 번 더 적용한다. 먼저 XY 평면 위에서의 그림자 거리를 구하면 $\sqrt{(\Delta x)^2 + (\Delta y)^2}$. 이 그림자 거리와 높이 차 $\Delta z$가 또 다른 직각 삼각형을 이루므로, 피타고라스를 다시 적용 → $\sqrt{(\sqrt{(\Delta x)^2 + (\Delta y)^2})^2 + (\Delta z)^2} = \sqrt{(\Delta x)^2 + (\Delta y)^2 + (\Delta z)^2}$.
규칙. $d(A, B) \le r$ 이면 $A$와 $B$ 사이에 간선이 있다 (직접 통신 가능). $d(A, B) > r$ 이면 간선이 없다.
비유. 무전기 두 대. 둘 사이가 송신 가능 거리($r$) 안에 있으면 직접 대화. 밖이면 직접은 못 하지만 — 누군가 중간에 있으면 중계가 가능하다 (다음 셀).

모든 쌍을 검사하면 간선 목록이 나온다

$n$개 정점에서 가능한 쌍은 $\binom{n}{2} = \frac{n(n-1)}{2}$개. 우리 문제는 $n = 20$이라 $190$쌍. 각 쌍에 대해 거리 계산 → $r$ 이하면 간선 추가. 총 시간 $O(n^2)$.

간선 생성 코드 (실제 JS) 
function buildEdges(points, r) {
  const edges = [];
  for (let i = 0; i < points.length; i++) {
    for (let j = i + 1; j < points.length; j++) {
      const d = distance(points[i], points[j]);
      if (d <= r) edges.push({ u: i, v: j, d });
    }
  }
  return edges;
}
CELL 3 · 개념

멀티 홉 — 한 다리 건너서도 연결

두 기기가 직접 통신 못 해도, 중간에 있는 기기가 중계해주면 통신 가능. 그래프 용어로 다시 말하면: $A$와 $B$ 사이에 직접 간선이 없어도 경로가 있으면 같은 연결 성분.

어떻게 모든 연결 성분을 한 번에 구하나?

두 가지 표준 방법:

  • BFS/DFS — 한 정점에서 시작해 도달 가능한 모든 정점을 방문, 그게 한 컴포넌트. 방문 안 한 다음 정점에서 다시 시작 → 다음 컴포넌트. 모든 정점이 방문될 때까지.
  • Union-Find (서로소 집합) — 모든 정점을 처음엔 각자 집합으로 두고, 간선마다 두 집합을 합친다. 끝나면 각 집합 = 컴포넌트.

이 페이지에서는 Union-Find를 쓴다 — 간선을 하나씩 보면서 단계별로 컴포넌트가 합쳐지는 과정이 시각적으로 더 명확해서.

CELL 4 · 자료구조

Union-Find (서로소 집합)

$n$개의 원소가 처음엔 각자 자기만의 집합($\{0\}, \{1\}, \{2\}, \dots$). 두 가지 연산만 지원:

  • find(x) — $x$가 속한 집합의 대표(루트)를 반환.
  • union(a, b) — $a$가 속한 집합과 $b$가 속한 집합을 하나로 합침.
핵심 아이디어. 각 원소가 "부모"를 가리키는 포인터를 갖는다. 부모를 계속 따라가다 자기 자신을 가리키면 거기가 루트 = 집합 대표. 두 원소가 같은 집합인지는 "둘의 루트가 같은가"로 판정한다.

예시 — 5개 원소에서 union을 두 번 했을 때

Union-Find 핵심 코드 (실제 JS) 
function makeUF(n) {
  const parent = Array.from({length: n}, (_, i) => i);

  function find(x) {
    while (parent[x] !== x) {
      parent[x] = parent[parent[x]]; // 경로 압축
      x = parent[x];
    }
    return x;
  }

  function union(a, b) {
    const ra = find(a), rb = find(b);
    if (ra === rb) return false;
    parent[rb] = ra; // 한쪽을 다른쪽 아래로
    return true;
  }

  return { parent, find, union };
}

두 가지 최적화 — 왜 거의 상수 시간이 되나

순진하게 구현하면 트리가 길게 늘어져 find가 $O(n)$이 될 수 있다. 두 가지 트릭으로 거의 $O(1)$로 만든다:

① 경로 압축 (path compression)

$x$에서 루트까지 올라가면서 만난 모든 노드의 부모를 루트로 바로 바꿔버린다. 다음에 또 $x$나 그 조상들을 find할 때 한 번에 도달.

② 랭크에 의한 합치기 (union by rank)

union할 때 작은 트리를 큰 트리 아래에 붙인다. 그래야 트리 높이가 천천히 자란다. "rank"는 트리 높이의 상한치라고 보면 된다 — 두 트리의 랭크가 같을 때만 합쳐서 1 늘어남.

직관: 거꾸로 큰 트리를 작은 트리 밑에 붙이면 큰 쪽 모든 노드가 한 단 깊어진다. 작은 쪽을 큰 쪽 아래에 붙이면 작은 쪽만 한 단 깊어지니 손해가 작다.

두 최적화를 함께 쓰면 $m$번의 연산이 $O(m \cdot \alpha(n))$로 끝난다. 여기서 $\alpha$는 아커만 함수의 역함수로, 실용적으로는 $n < 2^{65536}$일 때 $\alpha(n) \le 4$. 거의 상수.

CELL 7 · 마무리

정리

전체 알고리즘 한 줄로

  1. 모든 정점 쌍에 대해 거리 계산 → $r$ 이하면 간선 추가. $O(n^2)$
  2. Union-Find 만들고, 각 간선마다 union(u, v). 총 $O(E \cdot \alpha(n))$
  3. 각 정점의 find 결과로 그룹핑 → 컴포넌트 목록. $O(n \cdot \alpha(n))$

합쳐서 $O(n^2)$ — 정점 쌍 검사가 병목.

다른 응용

  • 네트워크 토폴로지 — LAN/WAN이 몇 개로 분리됐는지, 백본 라우터 장애 시 영향 범위.
  • 이미지 처리 — 같은 색 픽셀끼리 묶기 (flood fill).
  • 클러스터링 — 비슷한 데이터 포인트를 거리 기반으로 그룹화 (DBSCAN의 기초).
  • 그래프 알고리즘 — Kruskal 최소 신장 트리(MST)에서 사이클 판정.
변형 문제. $r$을 점점 키우면서 "처음으로 모두 연결되는 순간의 $r$"을 찾으면 그게 최소 신장 트리(MST)의 가장 긴 간선과 같다. — 클러스터링·이상치 탐지에서 유용한 관찰.
