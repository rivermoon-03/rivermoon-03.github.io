문제 5 · 최소 비용 작업 배정

$N$명의 작업자와 $N$개의 작업, 그리고 비용 행렬. 1대1로 배정하되 총 비용을 최소화하는 조합을 찾는다 — 최소 비용 최대 유량(MCMF)으로 변환해 푼다.

📋 문제 5 원문 (보고서 제출 기준)

$N$명의 작업자와 $N$개의 작업이 있고, 비용 행렬 $C_{ij}$가 주어졌을 때, 총 비용의 합이 최소가 되도록 하는 작업 배정 문제를 해결하시오.

요구사항

  1. 그래프 모델: 이 문제를 최소 비용 최대 유량(MCMF) 문제로 변환하는 방법을 자세히 설명하고, 소스 $S$, 싱크 $T$, 용량 $U$, 비용 $C$를 포함한 그래프 모델을 제시하시오.
  2. 알고리즘 구현: 변환된 그래프 모델을 기반으로, 최소 비용 최대 유량(MCMF) 알고리즘을 구현하시오. 구현 시, Bellman-Ford 알고리즘 또는 SPFA(Shortest Path Faster Algorithm)를 사용하여 잔여 그래프(Residual Graph)에서 최소 비용 경로를 찾는 과정을 반복해야 합니다.
  3. 최적 배정 및 비용: 최종적으로 배정된 작업자-작업 쌍의 목록과 최소 총 비용을 출력하시오.

💡 힌트

MCMF. 매번 최소 비용 경로(Shortest Path)를 찾아 해당 경로에 유량 1을 흘려보내는 과정을 반복.
음수 비용. 잔여 그래프에 음수 비용 간선이 생길 수 있으므로 Bellman-Ford/SPFA 사용. Dijkstra는 음수 비용에서 안 됨.
반복 횟수. 총 $N$번의 유량(매칭)을 찾으면 됨.
CELL 00 · 워밍업

먼저 — 최단 경로와 SPFA가 뭔가요?

가중치가 있는 방향 그래프에서 최단 경로를 찾는 알고리즘은 여러 가지 — 어떤 걸 써야 하는지는 음수 가중치 유무에 달려있다.

알고리즘 음수 가중치 시간 복잡도 전형적 용도
Dijkstra❌$O((V+E) \log V)$양수 가중치 일반 최단
Bellman-Ford✅$O(V \cdot E)$음수 OK, 음수 사이클 검출
SPFA✅평균 $O(E)$ (최악 $O(VE)$)실용에서 Bellman-Ford보다 빠름

왜 Dijkstra는 음수에서 안 되나?

Dijkstra는 "현재까지 거리가 가장 짧은 정점을 확정"하는 전략. 한 번 확정하면 다시 안 본다. 음수 간선이 있으면 — 더 늦게 발견한 우회로가 음수를 거쳐 더 짧을 수 있다. 확정한 거리가 틀려진다.

SPFA = Bellman-Ford의 큐 버전

Bellman-Ford는 모든 간선을 $V-1$번 본다. SPFA는 "거리가 바뀐 정점만 큐에 넣고 다시 확인" — 변화 없는 정점은 안 봄. 평균적으로 훨씬 빠르다. 우리는 SPFA를 쓴다.

SPFA 의사코드 
function spfa(graph, s):
    dist = [∞ for all v]
    dist[s] = 0
    queue = [s]
    inQueue[s] = true
    while queue not empty:
        u = queue.pop()
        inQueue[u] = false
        for each edge (u, v, cost):
            if dist[u] + cost < dist[v]:
                dist[v] = dist[u] + cost
                parent[v] = u
                if not inQueue[v]:
                    queue.push(v)
                    inQueue[v] = true
    return dist, parent

MCMF가 SPFA를 쓰는 이유는 잔여 그래프의 역방향 간선이 음수 비용을 갖기 때문 — 다음 셀들에서 자세히.

이 페이지에서 뭘 할 거예요

$N$명의 작업자가 있고 $N$개의 작업이 있다. 각 작업자가 각 작업을 할 때의 비용 $C_{ij}$가 행렬로 주어진다. 1대1로 모두 짝지어야 하고, 총 비용의 합을 최소화해야 한다.

사전 지식 없어도 OK. 문제 3에서 본 최대 유량 위에 "비용"을 얹은 확장이다. 셀 00에서 SPFA를 짚었고, 여기서부터 문제 정의·매칭·MCMF 변환 순으로 간다.

완성하면 이런 게 나옵니다

  • 비용 행렬 직접 편집 + 프리셋 (스왑이 일어나는 케이스 포함)
  • SPFA로 MCMF를 매 반복마다 최단 경로 찾아 1단위 흘려보내는 과정
  • 역방향 잔여 간선이 어떻게 "이전 배정을 되돌리는지" 단계별 시각화
  • 최종 배정 결과와 최소 총 비용 표시
CELL 1 · 개념

이분 그래프와 매칭

이분 그래프(bipartite graph) — 정점을 두 집합으로 나누고, 같은 집합 안에서는 간선 없음. 간선은 항상 서로 다른 집합 사이.

예: 작업자 집합(왼쪽) ↔ 작업 집합(오른쪽). 어떤 작업자가 어떤 작업을 할 수 있는지가 간선.

매칭(matching) — 어떤 간선도 같은 정점을 공유하지 않는 간선들의 모임. 완전 매칭(perfect matching) — 모든 정점이 정확히 하나의 간선에 속함. $N$ 명 / $N$ 작업이면 매칭 크기 $N$ = 완전 매칭.

위 예시: $W_1 \to T_2$, $W_2 \to T_3$, $W_3 \to T_1$ 매칭. 모든 정점이 정확히 하나에 속함. 가능한 매칭은 $N! = 6$가지.

CELL 2 · 개념

비용 행렬

모든 (작업자 $i$, 작업 $j$) 쌍에 대해 비용 $C_{ij}$가 주어진다. 행렬로 정리하면:

T₁T₂T₃
W₁519
W₂929
W₃991

파란 강조 칸은 한 가지 가능한 배정 — $W_1 \to T_2 (1)$, $W_3 \to T_3 (1)$. $W_2$도 어딘가 배정해야 하니 남은 칸 중에서 골라야 한다. 모든 가능한 매칭 중 합이 최소인 걸 찾는 게 목표.

CELL 3 · 유도

무식한 방법 — 모든 순열

$N$개의 작업을 $N$명의 작업자에게 1대1 배정하는 방법은 $N!$ 가지. 모든 경우를 시도해 비용을 계산하고 최소를 찾으면 된다.

$N=3$ 이면 $6$가지 — OK. $N=10$이면 $3.6 \times 10^6$ — 아직 가능. $N=20$이면 $2.4 \times 10^{18}$ — 우주의 나이로도 안 끝난다.

다항 시간 알고리즘이 필요하다. MCMF로 변환하면 $O(N^3)$ ~ $O(N^4)$ 수준. $N = 100$도 1초 내에 풀린다.
CELL 4 · 유도

MCMF 네트워크 모델

다음과 같이 그래프를 만든다:

  • $S \to W_i$: 각 작업자에 대해. 용량 1, 비용 0. — "각 작업자는 정확히 한 작업".
  • $W_i \to T_j$: 모든 (작업자, 작업) 쌍에 대해. 용량 1, 비용 $C_{ij}$.
  • $T_j \to T$: 각 작업에 대해. 용량 1, 비용 0. — "각 작업은 한 작업자만 받음".

$S$에서 $T$로 흘릴 수 있는 최대 유량은 $N$ (모든 작업자/작업이 짝지어졌을 때). 매번 1단위씩 흘려보내며 — 최소 비용 경로로 흘리면 누적 비용이 자동으로 최소가 된다.

흐름 1단위 = 작업자 한 명을 작업 하나에 배정. 총 흐름 $= N$이 되면 모든 배정 완료. 그 사이 누적 비용이 자동으로 최소화된다.

CELL 5 · 유도

잔여 그래프와 역방향 간선의 비용

문제 3에서 본 잔여 그래프 원리는 여기서도 똑같다 — 다만 비용이 추가된다.

간선 $(u, v)$에 용량 1, 비용 $c$로 1단위 흘렸을 때 — 잔여 그래프에는:
  • 전방향 잔여 $u \to v$: 용량 0 (이미 다 씀)
  • 역방향 잔여 $v \to u$: 용량 1, 비용 $-c$ — 흘린 걸 되돌리면 비용도 환불

왜 음수 비용인가?

그 간선을 통해 비용 $c$를 "썼었다". 흐름을 되돌리면 그 비용을 회수하는 셈 — 그러니 음수. 이 음수 비용 덕분에 알고리즘이 "이전 배정을 취소하고 더 좋은 조합으로 바꾸는" 경로를 자연스럽게 발견한다.

스왑이 일어나는 시나리오. 첫 반복에서 SPFA가 "$W_1 \to T_2$"를 골랐다고 하자 (비용 1). 나중 반복에서 $W_2$가 들어와야 하는데, $T_2$가 사실 $W_2$에게 더 잘 맞다면 — SPFA가 경로 S → W₂ → T₂(역방향) → W₁ → T₁ → T를 찾는다. 이 경로의 비용은 "$T_2$ 배정 비용 − 이전의 1 + $T_1$ 배정 비용". 즉 스왑이 한 번에 일어난다.

이게 MCMF가 단순 greedy(첫 매칭만 보는 것)보다 강력한 이유. 매번 음수 비용 경로까지 고려해 진짜 최소를 찾는다.

CELL 7 · 마무리

정리

전체 알고리즘 한 줄로

  1. 네트워크 구성: $S \to W_i$ (cap 1, cost 0), $W_i \to T_j$ (cap 1, cost $C_{ij}$), $T_j \to T$ (cap 1, cost 0).
  2. 잔여 그래프에서 SPFA로 $S \to T$ 최소 비용 경로 탐색.
  3. 경로 따라 1단위 흘리며 잔여 갱신 (역방향 간선에 음수 비용 자동 생성).
  4. $N$번 반복 (또는 경로가 더 없을 때까지). 누적 비용 = 최소 총 비용.
  5. 최종 배정: $W_i \to T_j$의 forward 간선 중 flow=1인 쌍이 답.

시간 복잡도

$O(\text{유량} \times \text{SPFA 1회})$ = $O(N \times V \cdot E)$. 우리 네트워크 $V = 2N+2$, $E = O(N^2)$ → 총 $O(N^4)$. $N=100$도 $10^8$ 정도로 충분.

다른 방법 — 헝가리안 알고리즘

같은 배정 문제를 $O(N^3)$로 푸는 전용 알고리즘. 듀얼 변수 + 매칭 갱신. 구현이 다소 복잡하지만 큰 $N$에서 더 빠르다. 본질은 MCMF와 같은 LP 쌍대성을 활용.

이게 실제로 어디 쓰여요?

  • 인력 스케줄링 — 직원을 시프트에, 의사를 환자에, 강사를 강의에.
  • 광고 입찰 — 광고주와 노출 슬롯을 가치 최대화로 매칭.
  • 물류 — 트럭에 배달 경로 1대1 배정.
  • 이미지 매칭 — 두 이미지의 특징점을 비용 기반으로 짝짓기.
