문제 1 · 최적 이진 탐색 트리

Optimal Binary Search Tree (OBST) — 자주 찾는 키는 위로, 덜 찾는 키는 아래로 두면 평균 탐색 시간을 최소화할 수 있다. 이 페이지에서는 그걸 동적 계획법으로 직접 만들어본다.

📋 문제 1 원문 (보고서 제출 기준)

주어진 확률 값들을 이용하여 최적 이진 탐색 트리(Optimal Binary Search Tree, OBST)를 구성하는 문제를 해결하시오.

입력 데이터

다음과 같은 성공 확률 $p$ 값들과 실패 확률 $q$ 값들이 정해져 있습니다.

01234567
p—0.040.030.050.030.150.150.05
q0.150.040.040.030.050.040.10.05

요구사항

  1. POA 방식 구현: 동적 계획법(Dynamic Programming) 방식을 사용하여 다음 세 가지 테이블을 채우는 과정을 구현하시오.
    • Weight Table
    • Cost Table
    • Root Table
  2. 트리 시각화: Root 테이블을 기반으로 구성된 최적 이진 탐색 트리(OBST)의 그림을 반드시 보고서에 첨부하시오.

💡 힌트

Weight $W[i, j]$: 키 $i$부터 $j$까지의 확률 합. 점화식 $W[i, j] = W[i, j-1] + p_j + q_j$ 로 효율적 계산.
Cost $C[i, j] = \min_{i < k \le j} \{ C[i, k-1] + C[k, j] + W[i, j] \}$. $k$는 해당 범위의 루트 노드.
CELL 00 · 워밍업

먼저 — 동적 프로그래밍(DP)이 뭔가요?

OBST 자체에 들어가기 전에, 우리가 쓸 도구인 동적 프로그래밍이 뭔지 짚고 간다. 이 셀은 OBST 얘기를 일부러 빼고, 순수하게 DP가 어떤 사고방식인지에만 집중한다.

알고리즘 설계 패러다임 한눈에

  • 탐욕(Greedy) — 매 순간 눈에 보이는 가장 좋은 선택. 빠르지만 항상 최적은 아님.
  • 분할 정복(Divide & Conquer) — 문제를 독립적인 부분으로 쪼개고, 각각 풀고, 합치기.
  • 동적 프로그래밍(DP) — 부분 문제로 쪼개되, 부분 문제들이 겹친다. 그래서 한 번 푼 답을 저장해 다시 안 풀게 한다.

DP가 적용되려면 두 가지 조건이 필요

1. 최적 부분 구조 (Optimal substructure) — 큰 문제의 최적해가 작은 부분 문제의 최적해로 구성된다.
2. 중복 부분 문제 (Overlapping subproblems) — 동일한 작은 문제가 풀이 과정에서 여러 번 등장한다.

조건 1만 있으면 분할 정복이면 충분하다 (예: 머지 소트). DP가 빛나는 건 조건 2까지 있을 때. 같은 부분 문제를 두 번 풀지 않으니, 중복이 심할수록 이득이 크다.

예시 1 — 피보나치의 재귀 트리

$\text{fib}(n) = \text{fib}(n-1) + \text{fib}(n-2)$. 그대로 재귀로 구현하면:

노랑 = 같은 부분 문제가 여러 번 호출됨. fib(2)는 5번이나 다시 풀린다.

$n$이 커지면 같은 노드가 지수적으로 늘어나 시간이 폭발한다. ($n=40$ 정도면 이미 수억 번.) — 중복 부분 문제가 한눈에 보인다.

두 가지 구현 방식

DP를 구현하는 정석적인 두 방법:

  • Top-down (메모화, Memoization) — 재귀 그대로 두되, 한 번 계산한 값을 표(맵·배열)에 저장하고 다음 호출에서 재사용. 자연스러운 사고 흐름.
  • Bottom-up (타뷸레이션, Tabulation) — 가장 작은 부분 문제부터 시작해서 위로 올라가며 표를 채움. 재귀 호출 오버헤드가 없고 더 빠르다. OBST는 이 방식을 쓴다.
피보나치 — Top-down vs Bottom-up 비교 
// Top-down (메모화)
const memo = {};
function fib(n) {
  if (n < 2) return n;
  if (memo[n] !== undefined) return memo[n];
  return memo[n] = fib(n-1) + fib(n-2);
}

// Bottom-up (타뷸레이션)
function fib(n) {
  const dp = [0, 1];
  for (let i = 2; i <= n; i++) {
    dp[i] = dp[i-1] + dp[i-2];
  }
  return dp[n];
}

DP 푸는 데 필요한 머릿속 절차

  1. 상태 정의: "어떤 부분 문제를 푸는가?"를 변수 몇 개로 표현. (예: $dp[i] = $ "fib($i$)의 값")
  2. 점화식: 큰 상태가 작은 상태들로 어떻게 만들어지는지 식. (예: $dp[i] = dp[i-1] + dp[i-2]$)
  3. 기저: 가장 작은 상태의 답을 직접 채움. (예: $dp[0]=0$, $dp[1]=1$)
  4. 채우는 순서: 점화식이 참조하는 작은 상태가 먼저 채워지도록 루프 방향 결정.
  5. 최종 답: 표의 어느 칸을 보면 되는지. (예: $dp[n]$)
OBST에서 이 절차가 어떻게 적용되는지는 셀 4~5에서 본격적으로 본다. 지금은 "표를 작은 것부터 큰 것까지 채우면 답이 나온다"는 그림만 머릿속에 두면 충분.

CELL 1 · 개념

이진 탐색 트리(BST)란?

이진 트리는 각 노드가 자식을 최대 2개 가지는 트리다. 이진 탐색 트리(Binary Search Tree, BST)는 거기에 한 가지 규칙을 더한 것:

모든 노드에 대해 — 왼쪽 자식 < 자기 자신 < 오른쪽 자식. 이 규칙 덕분에 검색이 빠르다.

예: 키 4를 찾는다고 해보자.

  1. 루트 5와 비교 → 4 < 5 이므로 왼쪽으로.
  2. 2와 비교 → 4 > 2 이므로 오른쪽으로.
  3. 4를 만남. 찾았다. 비교 횟수 3번.

같은 키 집합이라도 트리 모양에 따라 비교 횟수가 달라진다. 만약 4가 루트였다면 비교 1번에 끝났을 것이다. — 이게 다음 셀의 출발점.

CELL 2 · 개념

탐색 비용은 어떻게 셀까?

한 키를 찾는 비용 = 루트에서 그 키까지 내려가면서 한 비교 횟수. 루트면 1, 루트의 자식이면 2, 그 자식이면 3, …

그런데 키마다 찾는 빈도가 다르다. 어떤 키는 자주 찾고, 어떤 키는 거의 안 찾는다. 그러면 단순히 "어느 키를 찾든 비용을 똑같이 세는 것"은 공정하지 않다.

그래서 기대 탐색 비용(expected search cost)을 본다.
$\text{비용} = \sum_i (\text{키}_i \text{의 빈도}) \times (\text{키}_i \text{의 깊이})$

직관: 자주 찾는 키일수록 위(루트 가까이)에 두면 곱해지는 깊이가 작아져 이득. 반대로 거의 안 찾는 키는 깊이 묻어둬도 별 손해 없음.

그런데 단순히 "빈도 큰 순서대로 위에 두기"가 최적일까? 아니다 — BST는 왼쪽 < 자기 < 오른쪽 규칙을 지켜야 하므로 마음대로 못 둔다. 그래서 우리는 모든 가능한 트리 모양 중 비용이 최소인 것을 찾아야 한다.

$n$개의 키로 만들 수 있는 서로 다른 BST 개수는 카탈란 수로 매우 빠르게 늘어난다 ($n=7$이면 429가지). 전부 시도하는 건 작은 $n$만 가능. — 다음 셀에서 더 똑똑한 방법(DP)을 본다.

CELL 3 · 입력

문제 정의 + 입력 데이터

키는 $k_1, k_2, \dots, k_n$이고 오름차순이다 ($k_1 < k_2 < \cdots$). 각 키 $k_i$에 대해 성공 확률 $p_i$가 주어진다 — "검색할 키가 정확히 $k_i$일 확률".

그런데 입력 키가 존재하는 키 중 하나가 아닐 수도 있다. 예: 트리에 [1, 2, 5, 7]가 있는데 누가 4를 찾으면? 트리 어디에도 없다. 이런 "없는 키"의 경우를 다루기 위해 실패 확률 $q_i$도 정의한다.

$q_0$: 모든 키보다 작은 값을 찾을 확률 (예: $-\infty < x < k_1$)
$q_i$ (단, $1 \le i \le n-1$): $k_i < x < k_{i+1}$ 사이의 값을 찾을 확률
$q_n$: 모든 키보다 큰 값을 찾을 확률 ($x > k_n$)
비유. 전화번호부에서 이름을 찾는다고 해보자. 명단에 있는 이름은 "성공"(키 노드 $k_i$, 확률 $p_i$). 명단에 없는 이름은 "두 인접 이름 사이"의 어딘가에 떨어진다 (더미 노드 $d_i$, 확률 $q_i$). 예: "박씨"가 명단에 없으면 "박"은 "박" 알파벳 구간의 더미에 해당. — 키와 더미를 다 합치면 검색이 도착할 수 있는 모든 경우가 빠짐없이 분류된다.

시각적으로 표현하면 트리에 "더미 노드"(가짜 리프)를 붙인다. 키 노드 사이사이에 더미를 끼워넣어, 검색이 더미에 도달하면 "그 구간을 찾았는데 없다"는 뜻이 된다.

확장된 BST (Extended BST) 모양

키 3개($k_1, k_2, k_3$)와 더미 4개($d_0, d_1, d_2, d_3$)의 작은 예시:

모든 검색은 결국 키 노드(있는 키 찾음) 또는 더미 노드(없는 키 — 구간만 확인) 중 하나에 도달한다.

모든 확률의 합은 1이다 — 모든 경우가 빠짐없이 포함되니까:

$\sum_{i=1}^{n} p_i + \sum_{i=0}^{n} q_i = 1$

이번 문제의 입력 데이터

표를 보기 전에 — "$i$"는 뭐를 가리키나?
$i$는 왼쪽에서 몇 번째 위치냐를 나타내는 순번이고, 두 행에서 가리키는 대상이 다르다:
  • $p_i$ 행에서는 — "$i$번째 키" $k_i$ 자체를 찾을 확률 ($i = 1, \dots, n$). $i=0$은 키가 없어 "—".
  • $q_i$ 행에서는 — "$i$번째 틈" $d_i$에 검색이 떨어질 확률 ($i = 0, \dots, n$). 즉 $k_i$ 바로 오른쪽 구간.
모든 걸 줄세우면 q₀ → k₁ → q₁ → k₂ → q₂ → … → kₙ → qₙ 순서. 표는 "키 한 개 + 그 옆 틈 한 개"를 한 열에 묶어둔 것뿐. 그래서 $i=1$ 열의 $p_1$과 $q_1$은 별개 사건 — "$k_1$을 찾았다" vs "$k_1$ 옆 빈 구간을 찾았다".

아래 수직선 그림이 헷갈림을 가장 확실하게 푼다 — $p_i$는 점 위에, $q_i$는 구간 위에:

예: $i=1$ 열에서 $p_1 = q_1 = 0.04$ 였지만, 이 둘은 그림에서 보듯 서로 다른 위치(점 $k_1$ vs $k_1$ 옆 구간)에 대한 확률. 값이 우연히 같을 뿐.

같은 데이터를 표로도 — 각 열 $i$ = "$i$번째 키 + $i$번째 키 바로 오른쪽 틈"이라는 점만 기억하면 헷갈리지 않는다:

$i=0$ 열에 $p_0$만 "—"인 이유: 키는 1번부터 시작하니 "0번째 키"는 정의 안 함. 반면 틈은 가장 왼쪽($k_1$ 앞)부터 세기 시작하므로 $q_0$이 존재.

확률 분포 한눈에 보기

어떤 키가 자주 찾히는지(파랑), 어떤 구간이 자주 비어서 빠지는지(회색)를 막대 높이로:

합 = 0.50 (p) + 0.50 (q) = 1.00 ✓. 한눈에 봐도 $p_5, p_6$이 우뚝 솟아 있다. 즉 키 5, 6이 자주 검색된다 → 이 둘을 트리 위쪽에 두는 게 유리할 것이라고 직관적으로 예상할 수 있다. 실제 셀 7에서 그렇게 되는지 확인하자.

CELL 4 · 유도

DP를 OBST에 적용하기

셀 00에서 본 DP의 두 조건 — 최적 부분 구조와 중복 부분 문제 — 이 OBST 문제에도 그대로 들어맞는지 확인하자.

최적 부분 구조 ✓

OBST의 어떤 부분 트리도 그 자체로 OBST다.
만약 키 $k_{i+1}, \dots, k_j$에 대한 최적 트리의 루트가 $k_m$이라면, 그 왼쪽 서브트리는 키 $k_{i+1}, \dots, k_{m-1}$에 대한 최적 트리고, 오른쪽 서브트리는 키 $k_{m+1}, \dots, k_j$에 대한 최적 트리다.
비유. 회사 전체가 효율적이려면, 그 안의 모든 팀도 효율적이어야 한다. 만약 어떤 팀이 비효율적이면, 그 팀을 더 좋은 팀으로 갈아끼우는 것만으로도 전체가 개선되니까, 원래 "전체가 효율적이다"라는 전제와 모순이 된다. — OBST의 부분 트리에도 같은 논리. 그래서 우리는 안심하고 작은 부분 문제부터 풀어 큰 문제에 끼워넣을 수 있다.

그림으로 보면:

중복 부분 문제 ✓

"키 $k_{i+1}, \dots, k_j$로 만드는 최적 트리"라는 부분 문제는 인덱스 쌍 $(i, j)$로 표현된다. $n=7$이면 가능한 $(i,j)$ 쌍은 약 36개로 유한. 반면 모든 BST 모양은 $n=7$에서 카탈란 수만큼(429가지). 같은 부분 문제가 여러 큰 문제의 부분으로 반복 등장한다. ✓

예: 부분 문제 "키 $k_4, k_5$로 만드는 OBST" $\to (i,j)=(3,5)$ 는

  • $(0,7)$ 트리의 일부일 수도
  • $(2,5)$ 트리의 일부일 수도
  • $(3,7)$ 트리의 일부일 수도

있다. 그래서 한 번 풀어 표에 저장해두면 모든 곳에서 재사용된다.

부분 문제 격자 — 우리가 채울 표 모양

아래는 $(i, j)$ 쌍의 격자. 대각선 순서로 채워가는 게 핵심 — 작은 구간 길이 $d = j-i$부터:

같은 색의 칸들이 동시에 채워질 수 있다 (서로 의존 없음). $d=0$ 회색 (기저), $d=1$부터 점점 진해지며 마지막 $d=7$ 빨강 칸 $(0,7)$이 우리가 원하는 답.

그래서 DP 구조는 이렇게 잡힌다

  • 상태: $C[i][j]$ — "키 $k_{i+1}, \dots, k_j$로 만든 OBST의 최소 기대 비용"
  • 기저: $C[i][i] = 0$ (키 없음, 더미만 있음)
  • 점화식: 루트 후보 $m$을 모두 시도 → 다음 셀에서 식 유도
  • 채우는 순서: 구간 길이 $d = j-i$가 짧은 것부터 → 대각선 순
  • 최종 답: $C[0][n]$
CELL 5 · 유도

점화식 유도 (W, C, R)

구간 $[i, j]$를 "$i$번 더미와 $j$번 더미 사이의 키들 — 즉 $k_{i+1}, \dots, k_j$"로 보자.

W (Weight) — 부분 트리의 확률 합

$W[i, j]$ = 구간 $[i, j]$에 속하는 모든 확률의 합:

$$W[i, j] = q_i + \sum_{k=i+1}^{j} (p_k + q_k)$$

그림으로 보면 — 키와 더미를 일렬로 늘어놓고 $[i, j]$ 구간을 색칠한 것:

이걸 처음부터 매번 합하면 비싸므로, 점화식으로:

$$W[i, i] = q_i, \qquad W[i, j] = W[i, j-1] + p_j + q_j$$

오른쪽 끝을 한 칸 늘리는 셈 — 기존 구간에 새로 들어온 $k_j$와 $d_j$의 확률 두 개만 추가.

C (Cost) — 부분 트리의 최적 기대 비용

$C[i, j]$ = 구간 $[i, j]$ 키들로 만들 수 있는 OBST의 최소 기대 비용.

$i = j$이면 키가 없고 더미 $d_i$만 있으므로 비용 0:

$$C[i, i] = 0$$

$i < j$이면 어떤 키 $k_m$을 루트로 삼는다 ($i < m \le j$). 그러면 왼쪽 서브트리는 $C[i, m-1]$, 오른쪽은 $C[m, j]$. 루트가 새로 생기면서 그 아래 모든 노드의 깊이가 1씩 증가하니 $W[i, j]$만큼 추가 비용:

$$C[i, j] = \min_{i < m \le j} \big\{\, C[i, m-1] + C[m, j] + W[i, j] \,\big\}$$

왜 $W[i,j]$를 더하나? 직관 한 줄로: 한 노드의 비용 = "그 노드를 찾을 확률 × 깊이". 새로 루트를 씌우면 그 아래 노드들의 깊이가 모두 1씩 늘어난다. 깊이가 1 늘면 비용 증가량은 그 노드의 확률만큼이고, 이걸 구간 안 모든 노드(키 + 더미)에 대해 합하면 정확히 $W[i,j]$. — 그래서 어느 $m$을 고르든 공통으로 $W$만큼 더해진다.

그림으로 — 루트 $m$을 고를 때마다 트리가 다음과 같이 갈라진다:

R (Root) — 어느 $m$이 최적이었는지 기록

$R[i, j]$ = $C[i, j]$를 최소로 만드는 $m$의 값. 나중에 트리 구조를 복원할 때 쓴다.

핵심 DP 코드 (실제 JS) 
function buildOBST(P, Q) {
  const n = Q.length - 1;
  const W = Array.from({length: n+1}, () => Array(n+1).fill(0));
  const C = Array.from({length: n+1}, () => Array(n+1).fill(0));
  const R = Array.from({length: n+1}, () => Array(n+1).fill(0));

  // base case: W[i][i] = q_i, C[i][i] = 0
  for (let i = 0; i <= n; i++) W[i][i] = Q[i];

  // 구간 길이 d = j-i, 작은 것부터
  for (let d = 1; d <= n; d++) {
    for (let i = 0; i + d <= n; i++) {
      const j = i + d;
      W[i][j] = W[i][j-1] + P[j] + Q[j];

      let best = Infinity, bestK = i+1;
      for (let k = i+1; k <= j; k++) {
        const cost = C[i][k-1] + C[k][j] + W[i][j];
        if (cost < best) { best = cost; bestK = k; }
      }
      C[i][j] = best;
      R[i][j] = bestK;
    }
  }
  return { W, C, R };
}

구간 길이 $d = j-i$가 작은 것부터 채우면 $C[i, m-1]$과 $C[m, j]$가 이미 계산되어 있다. 다음 셀에서 한 칸씩 채워가는 과정을 직접 본다.

아래 세 테이블을 한 칸씩 채워나간다. 채우는 순서는 구간 길이 $d = j - i$가 작은 것부터 — 즉 대각선 순서. $d = 0$인 W의 기저 8칸 → $d = 1$인 W·C 7쌍 → $d = 2$인 6쌍 → … → $d = 7$인 W[0][7]·C[0][7] 1쌍. 총 64 스텝.

CELL 8 · 마무리

정리

총 기대 탐색 비용

$C[0][7] = \mathbf{2.54}$ — 즉 이 트리로 검색하면 평균적으로 키 하나를 찾는 데 2.54번의 비교가 필요하다. 다른 어떤 BST 구조로도 이 값보다 작게 만들 수 없다는 것이 DP의 보장.

시간 복잡도

삼중 루프 — 구간 길이 $d$, 시작 $i$, 루트 후보 $m$ — 그래서 $O(n^3)$. $n = 7$이면 60여 번이지만, $n = 1000$이면 약 $10^9$로 커지므로 큰 $n$에서는 부담된다.

Knuth 최적화 (1971): $R[i][j-1] \le R[i][j] \le R[i+1][j]$이라는 단조성을 이용하면 루트 후보 탐색을 줄여 $O(n^2)$로 떨어뜨릴 수 있다. — 이번 페이지에서는 다루지 않지만, 큰 $n$에서 OBST를 빌드해야 한다면 기억해둘 것.
