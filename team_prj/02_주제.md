# 02. 주제 — 서버 예약/할당 관리 시스템

## 1. 시스템 개요

**서버 예약/할당 관리 시스템**은 학과·연구실 단위로 보유한 서버 자원을 공정하고 효율적으로 나누어 쓰기 위한 **웹 기반 자원 예약 관리 소프트웨어**다. 학생·연구원은 본인이 속한 팀의 Quota 범위 안에서 서버를 예약하거나 즉시 할당받아 사용하고, 팀 관리자(교수)는 팀 사용 현황과 초과 요청을 관리하며, 서버 관리자는 시스템 전체의 자원·정책을 운영한다. 모니터링 시스템은 사용률을 자동 수집해 유휴 서버를 회수하고 만료된 예약을 자동 반납함으로써 자원 낭비를 줄인다.

---

## 2. 시스템 목표

| # | 목표 | 설명 |
|---|---|---|
| G1 | **공정한 자원 분배** | 팀 단위 Quota로 특정 팀·사용자의 자원 독점을 방지 |
| G2 | **예약·즉시할당 동시 지원** | 미리 잡는 예약형과 지금 쓰는 즉시형 두 흐름을 모두 지원 |
| G3 | **승인 워크플로우** | Quota 초과 요청은 팀 관리자 승인을 거쳐 처리 |
| G4 | **자원 낭비 최소화** | 유휴 서버 자동 회수, 예약 만료 자동 반납 |
| G5 | **동시 요청 일관성 보장** | 낙관적 잠금 기반으로 동일 서버 동시 예약 충돌을 안전하게 처리 |
| G6 | **사용자 알림 보장** | 예약 결과·승인 결과·회수 경고·만료를 사용자에게 즉시 통지 |
| G7 | **운영자 가시성** | 서버·팀·사용자 현황을 실시간 조회 가능 |

---

## 3. 시스템 범위

### 3.1 In-Scope (포함)

- 서버 등록·삭제·점검 스케줄 관리
- 서버 예약(예약형) 및 즉시 할당(즉시형) 처리
- 예약 취소·서버 반납·예약 만료 자동 반납
- 팀(랩) 단위 Quota 한도 관리 및 사용량 추적
- Quota 초과 시 승인 워크플로우 (요청 → 승인/거절 → 통지)
- **승인 요청 72시간 무응답 시 자동 거절** (타임아웃 정책)
- 유휴 서버 감지·경고 알림·자동 회수
- **동시 예약 충돌 처리** (낙관적 잠금)
- 사용자·팀·권한 관리 (학생/팀 관리자/서버 관리자)
- 알림 발송 (예약 결과, 충돌, 승인 결과, 유휴 경고, 만료)
- 실시간 서버 현황 및 예약 현황 조회

### 3.2 Out-Scope (제외)

- 실제 서버 원격 제어·SSH 접속·VM 프로비저닝
- 네트워크 / 방화벽 설정 자동화
- 외부 결제·과금 시스템 연동
- 타 학과·외부 클러스터 서버 연동
- 서버 내부 프로세스 단위 자원 제어
- 자원 사용량 기반 청구·정산

## 4. 핵심 가정 및 제약

| # | 가정 / 제약 | 설명 |
|---|---|---|
| A1 | 사용자는 반드시 1개 팀에 소속된다 | 무소속 사용자는 예약 불가 |
| A2 | Quota는 팀 단위로 부여되며, 팀 관리자가 팀원별로 세분화 가능 | 학생 개인 Quota는 팀 Quota를 초과할 수 없음 |
| A3 | 서버는 4개 상태만 가진다 | AVAILABLE / RESERVED / IN_USE / MAINTENANCE |
| A4 | 동시성 충돌은 **낙관적 잠금**으로 해결 | `Server.version` 필드로 충돌 감지, 패배자는 롤백 후 알림 |
| A5 | 승인 타임아웃은 **72시간 고정** | 미응답 시 시스템이 자동 거절하고 요청자에게 통지 |
| A6 | 알림은 시스템 내부 메시지 중심 | 외부 채널(이메일·Slack 등) 연동은 본 설계 범위 밖 |
| A7 | 점검 중 서버는 모든 예약 대상에서 제외 | MAINTENANCE 상태는 예약 불가 |

## 5. 핵심 도메인 용어

| 용어 | 정의 |
|---|---|
| **서버 (Server)** | 시스템이 관리하는 물리/가상 서버 자원. `id, name, ip, spec, status, version` |
| **예약 (Reservation)** | 사용자가 특정 서버를 특정 기간 사용하기로 한 약속. `id, userId, serverId, startTime, endTime, status` |
| **할당 (Allocation)** | 예약이 실제로 사용 가능한 상태로 변환된 것 (= IN_USE 진입) |
| **Quota** | 팀 또는 개별 사용자가 동시에 점유할 수 있는 서버 사용 한도(일 수 기준). 서버를 반납하면 사용한 만큼 자동으로 회복된다. `limit, used` |
| **승인 요청 (ApprovalRequest)** | Quota 초과 시 발생하는 팀 관리자 결재 건. `status ∈ {PENDING, APPROVED, REJECTED, AUTO_REJECTED}` |
| **유휴 회수 (Idle Reclaim)** | 사용률이 정책 기준 이하로 일정 시간 지속될 때 시스템이 서버를 자동 회수하는 절차 |
| **낙관적 잠금 (Optimistic Lock)** | `Server.version` 비교로 동시 변경을 감지하는 동시성 제어 방식. 패배 트랜잭션은 롤백 |
| **승인 타임아웃** | 승인 요청 후 72시간이 지나도 결재되지 않으면 자동 거절 처리하는 정책 |
| **모니터링 시스템** | 사용자 개입 없이 사용률 수집·유휴 감지·자동 회수·만료 반납을 수행하는 시스템 액터 |

## 6. 정책 파라미터

> 임의 수치(주기·임계치·재시도 횟수 등)는 모두 **시스템 정책 파라미터**로 정의하고, 명세서에서는 파라미터 이름으로 참조한다. 아래 "예시" 값은 본 설계에서 가정한 기본값이며, 운영 시 ADM이 변경 가능하다.

| 파라미터 | 의미 | 예시 값 | 사용 UC |
|---|---|---|---|
| `APPROVAL_TIMEOUT` | 승인 요청 자동 거절 임계 시간 | **72h** | UC08, UC17 |
| `APPROVAL_TIMEOUT_CHECK_INTERVAL` | 승인 타임아웃 점검 주기 | 10분 | UC17 |
| `IDLE_THRESHOLD` | 유휴 판정 사용률 상한 | 5% | UC15 |
| `IDLE_DURATION` | 유휴 판정 지속 시간 | 30분 | UC15 |
| `IDLE_DETECT_INTERVAL` | 유휴 감지 주기 | 5분 | UC15 |
| `IDLE_WARNING_GRACE` | 경고 후 회수까지 유예 시간 | 15분 | UC15 |
| `EXPIRY_CHECK_INTERVAL` | 예약 만료 점검 주기 | 1분 | UC16 |
| `EXPIRY_PRENOTIFY_LEAD` | 만료 사전 알림 발송 리드타임 | 1시간 | UC16, UC03-c |
| `METRIC_COLLECT_INTERVAL` | 사용률 수집 주기 | 1분 | UC14 |
| `METRIC_TIMEOUT` | 메트릭 응답 대기 한계 | 5초 | UC14 |
| `MISSING_ALERT_THRESHOLD` | 응답 연속 누락 시 경고 임계 | 10분 | UC14 |
| `AUTO_RETRY_LIMIT` | 즉시 할당 자동 재시도 횟수 | 3회 | UC05 |
| `CONFLICT_AUTO_GUIDE_LIMIT` | 충돌 시 대안 서버 자동 안내 반복 한도 | 3회 | UC03-d |
| `REALTIME_REFRESH_INTERVAL` | 현황 화면 자동 새로고침 주기 | 30초 | UC01 |
| `CONFLICT_ALT_LIST_SIZE` | 충돌 알림 시 안내할 대안 서버 수 | 최대 5건 | UC03-d |

> 명세 본문에 등장하는 "예시: …" 표기는 본 표의 예시 값을 가리킨다.
