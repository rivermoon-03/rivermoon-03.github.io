# 01. 작업 절차

> **과제 목적** — `source/` 자료에 정리된 *서버 예약/할당 관리 시스템*을 대학교 UML/소공 과제 수준의 산출물로 구체화한다. 즉, 주제를 명확히 하고, 액터·유스케이스 재료를 정리한 뒤, 유스케이스 다이어그램(`.drawio`)을 그리고, 표준형(Cockburn 축약) 유스케이스 명세서를 작성한다.

---

## 0. 산출물 한눈에

| # | 파일 | 종류 | 비고 |
|---|---|---|---|
| 01 | `01_절차.md` | 절차 문서 | **이 파일** |
| 02 | `02_주제.md` | 주제 구체화 | 시스템 개요/목표/범위/가정/용어 |
| 03 | `03_유스케이스_재료.md` | 재료 정리 | 액터·UC 목록·관계·매핑 |
| 04 | `04_유스케이스_다이어그램.drawio` | 다이어그램 | 액터-UC 관계 중심 |
| 10 | `10_서버임대_시나리오.md` | 시나리오 / 튜토리얼 | 도메인 개념 및 전체 흐름 설명 |
| 11 | `11_유스케이스_명세서.md` | **유스케이스 명세서 (기준)** | UC 20건 통합 명세 + 부록 A(구현 메모) |

**유스케이스 명세 총 20건** — 통합본은 11번. 과거 분할명세(`05~09_*.md`)는 11번으로 흡수되어 폐기되었다.

---

## 1. 작업 단계 (8 STEP)

각 STEP은 **한 번의 작업 턴 = 한 파일 작성**이다. 사용자는 STEP이 끝날 때마다 결과를 확인하고 다음 STEP 진행을 요청한다.

| STEP | 산출물 | 입력 | 출력 | 완료 기준 |
|---|---|---|---|---|
| **1** | `01_절차.md` | 사용자 결정 사항 | 본 문서 | 단계 표·체크포인트·작업 규칙 명시 |
| **2** | `02_주제.md` | `source/서버관리_문서.md` §1~§2 | 주제 구체화 문서 | 개요·목표·In/Out-Scope·가정·용어 5섹션 |
| **3** | `03_유스케이스_재료.md` | `source/서버관리_문서.md` §2~§3, §7, §8 | 재료 문서 | 액터 4명, UC 약 20~25개, 그룹·관계·매핑 표 완비 |
| **4** | `04_유스케이스_다이어그램.drawio` | STEP 3 산출물 | drawio XML | drawio.app에서 정상 렌더, 액터·UC·include/extend 모두 표시 |
| **5** | `11_유스케이스_명세서.md` | STEP 3 재료 | 통합 명세서 + 부록 A(구현 메모) | UC 20건 모두 표준 템플릿(주흐름/확장·실패 시나리오)으로 명세, 용어 통일 완료 |

---

## 2. 사용자 체크포인트

다음 시점마다 사용자가 결과를 확인하고 다음 단계로 진행 여부를 결정한다.

| 시점 | 확인 항목 |
|---|---|
| STEP 3 완료 후 | 액터/UC 목록·그룹 분류·include/extend 관계가 의도에 맞는가? |
| STEP 4 완료 후 | 다이어그램 레이아웃·관계 표시가 시각적으로 명확한가? (drawio.app으로 열어 확인) |
| STEP 5 완료 후 | 통합 명세서(`11_*.md`)에 누락/중복/모순된 UC가 없고, 부록 A의 구현 메모도 본문과 일관된가? |

> 체크포인트에서 수정 요청이 있으면, 해당 STEP만 다시 다듬는다 (이전 단계로 거슬러 올라가지 않음).

---

## 3. 명세 템플릿 — 표준형 (Cockburn 축약)

STEP 5~8에서 모든 유스케이스는 다음 9개 필드를 공통 사용한다.

| 필드 | 설명 |
|---|---|
| **ID** | UC04 등 고유 식별자 |
| **이름** | 유스케이스명 (한국어) |
| **주액터** | 트리거하는 액터 1명 |
| **우선순위** | 높음 / 보통 / 낮음 |
| **사전조건** | 시작 시점에 참이어야 하는 조건 |
| **주흐름** | 정상 시나리오 단계 (번호 매김) |
| **대안흐름** | 분기 시나리오 |
| **예외흐름** | 실패·오류 시나리오 |
| **사후조건** | 종료 시 시스템 상태 |
| **관련 UC** | include / extend / 의존 관계 |

---

## 4. 작업 규칙

- **한 턴 한 STEP** — 토큰/컨텍스트 절약을 위해 한 번에 한 파일만 작성.
- **source 우선** — `source/서버관리_문서.md`와 `source/서버관리_유스케이스.drawio`를 1차 출처로 삼는다. `기능정리.md`(AIOps 자료)는 본 과제 범위 밖이다.
- **고급 주제 포함** — 낙관적 잠금 기반 동시 예약 충돌 처리, 72시간 승인 타임아웃 자동 거절, 유휴 서버 자동 회수는 주요 유스케이스로 명시한다.
- **언어** — 본문·UC명·명세 모두 한국어. 단, UC ID(UC01 등)와 도메인 객체명(Server, Quota, Reservation 등)은 영문 유지.
- **다이어그램 스타일** — `source/서버관리_유스케이스.drawio`의 액터-UC 관계 중심 스타일을 따른다.
